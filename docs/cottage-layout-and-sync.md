# DOMIHOOD 私人小屋：布局与云端同步路线

## 当前版本

- 房间范围：先把单间装修体验做好。
- 摆放方式：3 × 3 网格定位；每件家具使用稳定的家具 ID 和格子坐标。
- 本地存储：domi_cottage_layout，保存主题、家具清单和位置。
- 兼容性：读取旧版只有 theme 和 furniture 的布局时，缺失的位置使用默认坐标补齐。
- 部署安全：装修页面继续使用客户端组件和浏览器本地存储，不要求 EdgeOne Pages 增加服务端运行时。

## 云端账号与跨设备同步（尚未启用）

建议等账号系统确定后再接入 Supabase。不要把昵称或浏览器 localStorage 当作用户身份，也不要在客户端放置服务角色密钥。

1. 确定正式身份认证方案（优先使用 Supabase Auth），让每个保存请求都能取得可信的用户 ID。
2. 建立 cottage_layouts 表，至少包含 user_id、layout_json、updated_at；对 user_id 开启 RLS，并只允许用户读写自己的记录。
3. 定义一个统一的布局存储接口（本地实现 + 云端实现），避免装修组件直接依赖具体数据库。
4. 登录后先加载云端布局；本地布局可作为首次迁移候选，用户确认后再上传，避免无提示覆盖已有数据。
5. 处理多设备同时编辑时的更新时间冲突，并提供保存失败提示与重试。
6. 在 Supabase 环境变量、RLS 策略和 EdgeOne 构建验证完成前，不开启云端写入。

## 发布前检查

- npm run build
- 在桌面与手机宽度检查弹窗、房间网格和家具选择状态。
- 验证旧版本地布局能正常加载，新增位置能保存并在重新打开后恢复。
- 确认部署预览通过后，再将功能分支合并到 main。
